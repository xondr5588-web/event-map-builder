- 사용자별 프로젝트 파일 API, 조건부 쓰기, 충돌 사본, 기기 간 동기화, 휴지통·복구.

## 실행해 통과한 검사

- `npm test`: 59개 통과. 기존 편집·파일·히스토리·저장소 회귀 검사 포함.
- `npm run build`: 개발용 정적 빌드.
- `VITE_NAVER_MAP_CLIENT_ID=… npm run build:site`: 비공개 Worker 빌드.
- `node scripts/verify-worker-build.mjs`: 내장 자산 응답, 익명 API 차단, 인증 파일·SW 확인.
- `npm run build:pages` + `node scripts/verify-public-build.mjs`: 공개 페이지에 편집기·지도 SDK·소유자 지도 ID가 없는지 검사.
- Playwright 테스트 파일 수집·문법 확인. 실제 실행 결과는 아래 한계 참조.

두 기기 충돌·휴지통·복구는 Node의 실제 IndexedDB 테스트 저장소와 메모리 R2 어댑터를 사용해 API와 클라이언트를 함께 검사했습니다. 실제 호스팅 R2와 실제 소유자 세션을 통한 브라우저 검증을 완료했다는 의미가 아닙니다.

## 아직 실행하지 못한 검사·반영

- 새 구현에 대한 데스크톱·Android·Galaxy·소형 화면·태블릿·가로 화면·iPhone WebKit Playwright 실행.
- 새 안내도 PNG·PDF의 실제 브라우저 생성 결과와 화면 검토.
- GitHub 원격 저장소 코드 반영과 새 CI 실행.
- 실제 사용자 세션·R2 연결 검사. 배포 서비스의 버전 8 배포는 2026-10-19 13:48 KST에 성공했습니다.

GitHub 쓰기 요청은 자동 승인 검토 시간 초과로 실행되지 않았고, 마지막 재시도에서 `Selected model is at capacity`라는 검토 실패 원인이 반환되었습니다. 안전하지 않다는 판정은 아니며 승인 검토를 우회하지 않았습니다. 직접 Git 전송도 사용 가능한 인증이 없어 실패했습니다.

비공개 Site의 저장 버전 8을 기존 소유자 전용 주소에 배포했습니다. 배포 서비스의 성공 응답을 확인했으며, GitHub 반영은 별도로 남아 있습니다. 후속 작업은 GitHub 쓰기 검토가 복구된 뒤 원격 반영 → CI 실행 → 실패 수정 → 브라우저 스크린샷·PDF 확인 → 필요 시 수정 버전 배포 순서로 진행합니다. 공개 GitHub Pages는 복구용 페이지를 유지합니다.

장소명 검색은 별도의 Naver Developers 검색 API 서버 비밀 환경변수가 필요합니다. 주소·좌표 검색에는 기존 네이버 지도 설정을 사용합니다. 안내 파일 생성은 사용자가 제공한 그림과 시설 배치를 사용하며 네이버 지도 타일을 캡처하지 않습니다.
