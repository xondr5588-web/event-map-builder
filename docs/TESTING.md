# 검증 기록

## 1.1.5 복사·붙여넣기 (2026-10-19)

마커 근처 복사/복제 버튼, 모바일 붙여넣기, 지도 탭 배치와 반투명 미리보기를 추가했다. 미리보기는 프로젝트·저장·JSON·PNG에 포함하지 않는다. 여러 마커/구역/동선의 상대 간격과 명시적 라벨 좌표를 같은 지도 투영으로 이동하며 수동 크기·회전·그룹·운영정보를 보존한다. 사본의 새 ID·고유 이름·잠금 해제, 복사 스냅샷 독립성, 프로젝트 한도, JSON 왕복·한 번의 Undo/Redo 및 배치 중 탭/드래그/핀치/터치 취소를 단위 테스트한다.

7개 화면/엔진에 복사·미리보기·취소·지도 탭 배치·빠른 복제·재실행 복구, 혼합 다중 선택·간격 유지, 입력창 단축키 보호·반복 키보드 붙여넣기 검증을 추가했다. Galaxy 구성은 실제 CDP touch 입력과 탭으로 동작을 확인하며 미리보기/배치 컨트롤 화면을 보고서에 첨부한다. 로컬 단위 **47개** 및 프로덕션 빌드를 통과했다. 전체 브라우저 결과는 해당 커밋의 Actions 보고서를 기준으로 한다.

## 1.1.4 마커 직접 편집 (2026-10-17)

이름 라벨 클릭/터치 → 지도 위 입력, 일반 선택 모드의 즉시 드래그, 선택 마커 옆 잠금/해제, 잠금 배지를 추가했다. 이름 수정은 객체명·표시 라벨을 함께 반영하며 기존 속성에서 개별 수정은 유지한다. 한글 IME 조합 중 Enter는 저장하지 않고, 입력 후 외부 클릭은 위치 미리보기 생성 전에 이름을 확정한다.

추가 단위 검증은 편집 모드 없는 드래그·한 번의 Undo, 라벨 탭, 잠금/지도 이동/다중 선택, 취소·두 번째 손가락의 미리보기 폐기, 이름 확정과 이동 스냅샷의 순서를 검사한다. 기존 검증을 포함한 로컬 단위 **39개**와 비공개 빌드를 통과했다. 7개 화면/엔진 브라우저 시나리오는 이름 저장/취소/외부 클릭/재실행과 JSON 보존, 직접 이동/Undo·Redo/잠금·해제/취소를 검사한다. Galaxy 구성은 CDP의 실제 touch 입력으로 새 직접 이동을 실행한다. 최종 브라우저 결과는 해당 커밋 Actions 보고서를 기준으로 한다.

## 1.1.3 수동 크기·마커 일관성 (2026-10-16)

전체/선택 마커를 16~96px로 지정하는 지도 내 슬라이더를 추가했다. 명시적 수동 크기는 자동 상한·지도 확대와 별개이며 구역·동선·글자를 변경하지 않는다. 드래그 미리보기는 렌더러 안에서만 유지하고 손을 놓으면 한 번의 저장·Undo로 반영한다. 개별 크기 해제, 전체 크기 통일, 잠금 보존을 지원한다.

단위 검증: 확대 6/17/21의 고정 크기, 개별 우선순위, 동선·글자 영향 없음, 구버전 기본값·잘못된 범위 보정, JSON 왕복·Undo/Redo·배치정보 보존. 브라우저 검증: 7개 화면/엔진에서 실제 슬라이더 드래그 미리보기·한 번의 Undo·Redo·개별 조절·재실행·JSON 내보내기. Galaxy에서는 실제 touch 이벤트로 드래그한다. 경찰·소방 휘장과 의료소·셔틀 정류장 표식은 지도·범례·PNG 및 기존 기능 회귀에 포함한다. 2026-10-17 최종 검증: 단위 **34개 통과**, 편집기 **86개 통과**(엔진별 의도적 제외 19개), 비공개 로그인 보호 **14개 통과**, 공개 백업 **14개 통과**. 총 브라우저 검증 **114개 통과**, 공개·비공개 프로덕션 빌드 및 공개 빌드의 SDK/편집기 미포함 검사 통과. [검증 실행](https://github.com/xondr5588-web/event-map-builder/actions/runs/38992655390)의 각 Playwright 보고서에 증거를 보관한다.

19종 전체를 같은 크기의 SVG 갤러리(40px/24px)로 렌더링해 육안 검토했다. 실제 기기와 네이버 SDK 검증 범위는 아래 한계를 유지한다.

## 1.1.2 자동 크기 조절 (2026-10-16)

확대 17에서 통제지점 심볼과 라벨이 지나치게 커지는 문제를 수정했다. 이전 도면에도 기본으로 자동 크기를 적용하며, 심볼·글자·긴 라벨의 화면 크기를 따로 제한한다. 원문·좌표·배치 정보를 보존하고 기존 비례 표시를 명시적으로 선택할 수도 있다.

## 자동 검증 범위

- 단위·저장소·서버 테스트: 데이터 마이그레이션, 원문 백업, 중복 ID, 잘못된 좌표/JSON/스키마 거부, import/export, Undo/Redo·정렬·스타일, 여러 창의 저장 충돌, 중단 저널 복구, 휴지통·버전 포함 전체 백업, 750개 객체의 저장과 버전 제한, 장소 검색 서버의 출처·비밀키 보호.
- 지도 어댑터: 네이버 SDK의 움직이는 pane offset과 고정 SVG viewport 간의 좌표 변환 회귀 테스트.
- 늦게 도착한 인증 실패로 SDK 내부가 무효화되어도 오류 안내·좌표 편집·저장을 유지하고, 다시 시도하면 SDK 재로드 및 주소 검색이 복구되는지 검증한다. 가짜 SDK 응답을 사용하는 이 시나리오만 Service Worker를 차단하며, 실제 오프라인 캐시는 별도 테스트에서 검증한다.
- Playwright: PC 1440×900, Android Pixel 393×851, Galaxy 412×915, 작은 화면 320×568, 태블릿 834×1194, 가로 844×390, iPhone 13 WebKit 구성. 각 구성에서 생성·속성·Undo/Redo·재실행·JSON 왕복·인쇄 미리보기·버전 복구·잠금·레이어·화면 회전을 검증한다.
- Chromium의 Android touch 입력: 한 손가락 이동, 두 손가락 확대, 마커 이동, touchCancel 후 원상 복귀.
- Chromium 6개 구성: Service Worker 준비 후 네트워크를 끊고 다른 URL로 다시 진입해 저장 도면을 불러온다.
- PC 추가: 두 창의 동시 변경을 별도 사본으로 보존, 구역 30 + 동선 80 + 마커 500개 도면에서 이동·확대/축소, 마커 추가 후 Undo/Redo 20회, 새로고침 복구.
- 동일 대량 도면을 A4/A3 세로·가로로 PDF 렌더링하여 각각 1페이지인지 검사한다.

특정 엔진 전용인 터치·PDF·오프라인 테스트는 해당 프로젝트에서 실행하며 나머지 구성에서 의도적으로 건너뛴다. HTML 보고서의 skip은 이 구분에 해당한다. 모든 화면에서 공통 편집 시나리오와 오류 검사를 수행한다.

```sh
npm ci
npm test
npm run build
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

CI도 같은 순서로 실행하며, 테스트를 통과한 빌드만 배포한다. 최신 통과 여부는 저장소 Actions의 `verify` 작업과 `playwright-report` artifact가 기준이다.

## 실제 네이버 SDK 확인

기존 공개 Client ID로 HTTPS 테스트 origin에서 실제 네이버 Maps SDK, Geocoder, 인증 응답, 지도 타일 일부의 표시와 저작권 표시를 확인했다. `경상남도 김해시 김해대로 2401` 검색이 김해시청을 반환했다. 마커 생성 후 지도 이동 40×25px에 대해 SVG 이동 40.01×25.01px를 확인했다. 해당 흐름의 JavaScript pageerror는 없었다.

이 환경은 외부 통신에 프록시가 필요했고 일부 지도 타일 서버 요청이 시간 초과되어 전체 타일의 안정적인 로드를 인증할 수는 없었다. 일반 편집 자동 회귀 테스트는 외부 API 할당량·네트워크에 좌우되지 않도록 배경 없는 좌표 도면 모드(`?map=offline`)를 사용한다.

10월 1일 GitHub Pages를 실제 활성화하고 `deploy` 성공 및 공개 앱 실행을 확인했다. 공개 도메인에서는 기존 Client ID의 네이버 인증이 거부되었다. 이때 SDK 정리 과정의 예외가 오류 안내까지 중단시키는 문제를 발견해 보완했고, 태블릿에서 재시도 버튼이 속성창에 가려지는 배치도 수정했다. 네이버 Cloud의 해당 Application 설정 확인 전에는 공개 사이트의 지도·주소 검색이 정상이라고 판단할 수 없다.

## 검증의 한계

- 화면 크기 및 Chromium/WebKit 브라우저 엔진 검증이며 실제 Android/iPhone/iPad 하드웨어의 인증은 아니다.
- 카메라·GPS 실제 기기 권한, OS 홈 화면 설치 화면, 기기별 공유/다운로드 앱, 실제 프린터 출력은 장치 접근이 필요하다.
- 네이버 상호·시설명 검색은 별도 NAVER Developers 비밀키가 필요하다. 제공한 서버는 가짜 upstream 응답으로 자동 검증했으며 실제 비밀키를 사용한 서비스 호출은 포함하지 않았다.
- 브라우저 용량 정책·저장소 강제 삭제·초대형 프로젝트의 모든 조합을 보장하지 않는다. 지원 한도와 별개로 실제 성능 검증 도면은 610개 객체였다.
- 배포 완료 여부는 Pages Actions의 `deploy` 결과와 실제 앱 주소에서 확인한다. 최초 Pages 활성화에는 저장소 관리자 설정이 필요하다.
