소유자의 ChatGPT 계정으로 로그인해야 이용할 수 있습니다. 다른 계정은 허용되지 않습니다.

**기존 주소:** https://xondr5588-web.github.io/event-map-builder/  
기존 데이터 백업과 비공개 앱 안내만 제공합니다. 지도 SDK와 소유자의 지도 Client ID를 포함하지 않습니다. 기존 프로젝트를 옮기는 방법과 네이버 허용 도메인 변경은 [비공개 운영 전환](docs/PRIVATE-ACCESS.md)을 확인하세요.

## 시작하기

Node.js 24 LTS 권장 (최소 22.12), npm이 필요합니다.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

개발 주소는 `http://localhost:5173`입니다. 같은 Wi-Fi의 모바일 기기에서는 개발 PC의 IP로 접속할 수 있습니다. 네이버 지도에 해당 주소를 등록해야 하며, PWA·파일 공유·위치 권한 등은 HTTPS 또는 localhost에서 사용하세요.

```sh
npm test                  # 데이터·히스토리·저장소·장소 검색 서버 테스트
npm run build             # dist/ + 버전별 오프라인 캐시 생성
npx playwright install --with-deps chromium webkit
npm run test:e2e           # 실제 브라우저, 7개 화면 구성
npm run preview           # 빌드 결과 확인
npm run format            # 소스 정리
```

`index.html`을 파일로 직접 열지 말고 개발 서버 또는 배포 주소를 사용하세요. 웹 서버는 `dist/`를 정적 파일로 제공하면 됩니다. 자산 경로는 상대 경로여서 GitHub Pages 하위 경로에서도 동작합니다.

## 1.1 행사 운영 업무 기능

- **운영계획 탭**: 행사 장소·기간·시간, 주최/주관·대행사·총괄·비상 연락처·방문객, 문서번호·개정번호·작성/검토/확정 상태를 도면과 함께 저장합니다.
- **현장 배치 정보**: 객체마다 담당팀·연락처·시작/종료시간·배치 상태·업무지시를 입력합니다. 인력 마커 하나에 여러 명을 배정할 수 있고 다중 선택으로 일괄 변경할 수 있습니다.
- **운영 집계**: 지도에 표시 중인 요소의 인원·담당팀·시설 수량·동선 길이·라바콘 예상 수량을 집계합니다. 담당팀 미지정과 진입/출차·의료 지점 누락을 검토할 수 있습니다.
- **주차 수용대수**: 주차 구역 속성에 확정 대수를 입력합니다. 비워 두면 면적과 계획면적(기본 30m²/대)으로 추정하고, 추정 여부를 명시합니다. 운영계획에서 계획면적을 조정할 수 있습니다.
- **배치표 CSV**: 숨긴 객체까지 포함하여 좌표·담당팀·인원·시간·주차대수·업무지시·표시 여부를 Excel 등에서 열 수 있는 UTF-8 CSV로 내려받습니다.
- **운영계획서 / PDF**: 문서 정보·집계·팀별 배치·상세 업무지시를 A4 가로 문서로 출력합니다. 지도 출력은 기존 **인쇄 / PDF**에서 A4/A3, 세로/가로와 범례를 선택합니다.
- **현장 심볼**: 반사조끼를 입은 주차관리원·안전모를 쓴 안전요원·안내요원, 차량·셔틀·구급차·소방차·운영본부·집결지 등을 구분합니다. 경찰부스에는 실제 경찰 휘장을 사용합니다. 도구·지도·범례는 같은 그림을 사용합니다. [출처](docs/SYMBOLS.md)
- **추가 도구**: 통제 구역·보행 안전구역·긴급차량 동선·교통약자 동선·경찰부스·소방 대기소·운영본부·비상 집결지·셔틀 승하차장·안내요원.

### 지도 축척과 요소 크기

마커·라벨·라벨 간격·선 굵기·화살표·라바콘 장식은 지도 확대 한 단계마다 2배, 축소하면 절반 크기로 표시됩니다. 지리 좌표와 실제 거리 간격은 유지됩니다. 터치 선택 영역과 꼭짓점 손잡이는 최소 크기를 유지합니다.

**더 보기 → 지도 · 저장 설정**에서 전체 요소 크기와 **현재 지도 확대 수준을 기준으로**를 조정하세요. 객체별 **요소 크기 (%)**도 바꿀 수 있습니다. 화면에서 일정한 크기가 필요하면 축척 연동을 끕니다. 이전 도면은 저장 당시 확대 수준을 기준으로 자동 설정해 처음 열었을 때 기존 배치 크기를 유지합니다.

새 운영정보와 축척 설정은 기존 schemaVersion 1에 호환되는 선택 필드입니다. 예전 JSON과 브라우저 데이터는 기본값을 채우며, 원문 백업·버전 복구·Undo/Redo 흐름을 유지합니다.

## 현장에서 사용하기

1. 상단에 도로명/지번 주소 또는 `35.2017194, 128.2259361` 형식의 좌표를 입력합니다. 장소명 검색은 아래 별도 서버 설정이 필요합니다.
2. **만들기**에서 도구를 선택하고 지도를 탭합니다. 구역은 3점, 동선은 2점 이상 놓고 **완료**를 누릅니다. 마커는 연속 배치합니다.
3. 객체를 선택하고 **위치 편집**을 누릅니다. 객체·흰 꼭짓점·라벨을 드래그합니다. 작은 **+**로 점을 추가하고, 꼭짓점을 선택해 삭제합니다.
4. 속성에서 이름·라벨·색상·회전 등을 바꿉니다. 잠근 객체는 잠금 해제 후 편집할 수 있습니다.
5. 중요한 변경 후 **버전 저장**을 누르고, **더 보기 → 전체 프로젝트 백업**으로 파일도 보관합니다.

### 스마트폰·태블릿

- 하단 **만들기 / 객체 / 운영계획 / 프로젝트**로 시트를 열고 닫습니다. 도구를 고르면 시트가 닫혀 지도를 넓게 사용할 수 있습니다.
- 선택 객체의 **속성 → 현장 배치 정보**에서 팀·인원·운영시간·업무지시를 입력하고 **운영계획**에서 집계·배치표·계획서를 확인합니다.
- 빈 지도를 한 손가락으로 밀어 이동하고, 두 손가락으로 확대·축소합니다. 생성 중에도 지도 이동이 가능합니다.
- 탭은 선택, 길게 누르기는 위치 편집입니다. **위치 편집** 중에만 선택한 객체가 움직이므로 탐색할 때의 실수를 줄입니다.
- 손가락으로 가리는 위치는 **중심에 배치 / 중심에 점 추가**와 확대 버튼을 사용하세요.
- 가로모드에서는 도구 시트가 옆으로 이동합니다. 편집 중 검색창은 접혀 지도 공간을 확보합니다.
- Android: 브라우저 메뉴 → 앱 설치/홈 화면에 추가. iPhone·iPad: Safari 공유 → 홈 화면에 추가.
- 파일 가져오기는 기기의 파일 선택기를 사용합니다. 내보내기 파일은 다운로드/파일 앱에 저장됩니다. 파일 공유는 지원 브라우저에서 공유 시트를 엽니다.

## 데이터 보호와 기존 버전 호환

- 자동저장은 IndexedDB `event-map-builder-v1`에 기록됩니다. 350ms 디바운스, 쓰기 직렬화, 트랜잭션과 revision 비교를 사용합니다.
- 변경 직후 localStorage 복구 저널도 작성합니다. 비정상 종료 후 다음 실행 때 복구하며, 다른 창의 변경과 충돌하면 사본을 만듭니다. 저장 중 객체 드래그는 임시 상태로 다뤄 중간 좌표가 저장되지 않습니다.
- 수동 버전과 주기적 복구 지점은 최근 40개를 보관합니다. 가져온 예전 버전 기록은 자동 삭제하지 않습니다. 프로젝트 삭제는 휴지통으로 이동합니다.
- 기존 `event_map_*_autosave`, `event_map_*_versions`를 발견하면 원문을 먼저 백업한 뒤 한 번만 이전합니다. 원래 localStorage 항목은 삭제하지 않습니다.
- v10의 `areas/lines/markers`, 더 오래된 `parking/flow/staff`, 자동저장·버전 envelope, 현재 schemaVersion 1 JSON을 지원합니다. 좌표·라벨 오프셋·라벨 지리 위치·회전·스타일을 가능한 범위에서 보존합니다.
- 중복 객체 ID는 교체하고 알려줍니다. 잘못된 좌표·점 개수·알 수 없는 스키마 버전·JSON 오류는 전체 가져오기를 중단합니다. 일부 데이터만 조용히 버리지 않습니다.
- 전체 백업은 프로젝트·휴지통·버전·구버전 원문을 포함합니다. 가져오기는 새 프로젝트 ID를 부여해 현재 작업을 덮어쓰지 않습니다. 개별 파일 최대 50MB, 백업 프로젝트 300개, 프로젝트 객체 10,000개/전체 꼭짓점 200,000개 한도입니다. 이 한도는 쾌적한 성능을 보장하는 수치가 아닙니다.
- **자동 이전은 동일한 브라우저·동일한 origin에서만 가능합니다.** `file://`, 다른 도메인/포트, 다른 기기에 저장했던 데이터는 구버전에서 JSON을 내보내 새 앱에서 가져오세요. Safari 설치 앱과 브라우저의 저장 공간도 다를 수 있습니다.
- 브라우저 데이터 삭제·기기 분실까지 로컬 저장으로 보호할 수는 없습니다. 현장 투입 전·후 전체 백업 파일을 별도로 보관하세요. 설정의 저장 공간 보호 요청은 브라우저 지원 여부에 따릅니다.

## 네이버 지도 설정

브라우저는 `https://oapi.map.naver.com/openapi/v3/maps.js`를 `ncpKeyId`로 로드한 뒤 `maps-geocoder.js`를 순서대로 로드합니다. 공개 식별자는 환경 변수로만 지정합니다. 기본값은 비어 있으며, 설정하지 않으면 지도 API를 호출하지 않습니다.

1. NAVER Cloud Platform의 **Maps** Application에서 **Dynamic Map**, 주소 검색에 필요한 **Geocoding** 권한과 사용 한도를 확인합니다.
2. Web 서비스 URL/허용 도메인에 실제 사용하는 주소를 등록합니다. 비공개 앱: `https://field-event-map-private.sugaryseed3.chatgpt.site`. 기존 GitHub Pages 도메인의 허용은 제거하세요. 개발에 필요한 주소만 별도로 등록합니다. 콘솔 안내에 맞춰 배포 도메인과 개발 주소를 각각 등록하세요.
3. 새 식별자를 사용할 경우 `.env.local`에 `VITE_NAVER_MAP_CLIENT_ID=공개_식별자`를 넣고 다시 빌드합니다. GitHub Pages 백업 빌드는 지도 식별자를 사용하지 않습니다. 비공개 앱을 빌드할 때만 이 값을 지정합니다.
4. 브라우저용 식별자는 공개됩니다. 허용 도메인 제한·할당량·사용량 알림을 설정하세요. Client Secret 등 비밀값을 `VITE_*`, 소스 또는 브라우저에 넣지 마세요.

지도 네트워크·인증 오류가 나면 안내와 **지도 다시 연결** 버튼을 표시하고 배경 없는 좌표 도면에서 작업을 이어갈 수 있습니다. 네이버 지도 타일·주소 검색은 온라인 연결이 필요합니다.

인증 오류가 계속되면 Maps Application의 공개 식별자가 올바른지, **Web 서비스 URL**에 `https://field-event-map-private.sugaryseed3.chatgpt.site`가 등록되어 있는지 확인하세요. 사용 중지·할당량 초과·Dynamic Map/Geocoding 미선택 여부도 확인합니다. 설정을 고친 뒤 앱의 **다시 시도**를 누르면 SDK부터 다시 연결합니다. 비밀키는 앱에 입력할 필요가 없습니다.

### 장소명 검색 (선택적 서버)

NAVER 지도 Geocoder는 주소 검색용입니다. 상호·시설명 검색은 NAVER Developers **검색 API(지역)**의 별도 Client ID/Secret과 서버가 필요합니다. 안전한 중계 서버 `server/place-search.mjs`를 제공합니다.

```sh
cp server/.env.example server/.env
# server/.env에 NAVER_SEARCH_CLIENT_ID, NAVER_SEARCH_CLIENT_SECRET,
# ALLOWED_ORIGINS를 설정합니다. 저장소에는 커밋하지 마세요.
node --env-file=server/.env server/place-search.mjs
```

HTTPS 역방향 프록시 뒤에 서버를 배포하고, 프런트엔드의 `VITE_PLACE_SEARCH_URL=https://검색서버/search`를 설정해 재빌드합니다. Actions에서는 Repository Variable `PLACE_SEARCH_URL`을 사용합니다. `ALLOWED_ORIGINS`는 경로 없이 정확한 origin을 쉼표로 구분합니다. 서버는 허용 출처·메서드·검색어 길이를 검사하고, IP별/전체 요청 수와 외부 요청 시간을 제한합니다. 응답은 저장·캐시하지 않습니다. 운영 프록시에서도 사용량 제한을 적용하세요. GitHub Pages 자체는 이 서버를 실행할 수 없습니다.

서버를 설정하지 않아도 지도·주소·좌표 검색 및 나머지 편집 기능은 동작합니다.

## 인쇄·PDF·PNG

**출력**에서 A4/A3와 세로/가로, 범례를 선택하고 **PDF / 인쇄**를 누릅니다. 제목과 운영 메모, 날짜, 사용한 종류별 범례가 포함됩니다. 인쇄 미리보기에서도 지도를 이동·확대해 출력 구도를 조정할 수 있습니다.

브라우저 인쇄 창에서 배경 그래픽을 켜고 머리글/바닥글을 끄세요. 실제 출력기의 비인쇄 영역과 브라우저에 따라 여백이 다를 수 있습니다. 지도 로드가 끝난 뒤 미리보기에서 결과를 확인하세요. 지도 제공자 로고·저작권 표시는 유지됩니다.

PNG는 **직접 작성한 운영요소만** 투명 배경으로 내보냅니다. 지도 타일을 다운로드하거나 캔버스로 우회 캡처하지 않습니다. 지도와 함께 외부로 배포하는 출력물의 이용 범위는 네이버 지도 이용약관을 확인하세요.

## PWA·오프라인

비공개 배포(`npm run build:private`)와 공개 백업 페이지(`npm run build:pages`)에서는 인증 보호를 위해 아래 오프라인 셸 캐싱을 사용하지 않습니다. 기존 셸 캐시를 정리하고 모든 새 요청을 호스팅 서버로 전달합니다. 열려 있는 편집기의 로컬 작업·저장은 계속 가능합니다. 다시 열 때는 온라인 인증이 필요합니다.

일반 개발 빌드의 동작은 다음과 같습니다.

manifest, 192/512 아이콘, maskable·Apple 아이콘과 Service Worker를 포함합니다. 온라인에서 한 번 실행한 뒤 앱 UI와 저장된 프로젝트를 오프라인으로 다시 열 수 있습니다. 캐시는 자체 HTML/CSS/JS/아이콘만 포함하며 지도 SDK·타일·검색 응답을 캐시하지 않습니다. 지도 없이 좌표 기반 편집·백업이 가능하고 온라인 복귀 후 지도를 다시 연결할 수 있습니다.

새 버전이 준비되면 **더 보기 → 업데이트 적용**을 사용합니다. 적용 전에 저장을 완료합니다. 오프라인 캐시는 빌드 파일 해시로 구분합니다.

## 배포

저장소의 `.github/workflows/pages.yml`은 main push 때 단위 테스트 → 편집기/비공개 접근 E2E → 공개 백업 전용 빌드/검사/E2E → Pages 배포를 수행합니다. Pages에는 편집기를 배포하지 않습니다. 비공개 앱은 `.openai/hosting.json`으로 식별되는 Sites 소유자 전용 정책을 유지하며 별도로 배포합니다. `npm run build:private`에는 `VITE_NAVER_MAP_CLIENT_ID`를 지정하세요. PR은 검증만 수행합니다. 테스트가 실패하면 배포하지 않습니다. 보고서와 빌드 파일은 Actions artifact로 보관합니다.

최초 한 번 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택하세요. 이후 main에 반영하면 자동 배포됩니다. 환경 변수 변경 후 Actions를 수동 실행해도 됩니다. 저장 데이터의 자동 이전을 위해 기존 도메인을 유지하는 것이 좋습니다.

자체 서버라면 `dist/`를 HTTPS로 제공하세요. `index.html`, `sw.js`에는 재검증 캐시 정책을, 해시가 있는 자산에는 긴 캐시 수명을 권장합니다. 배포 때 기존 사용자 데이터를 삭제하는 스크립트를 추가하지 마세요.

상태 관리와 SVG 편집기가 작은 모듈로 분리된 JavaScript/Vite 구성입니다. UI 프레임워크 런타임 없이 실행합니다. 객체 DOM을 ID로 재사용하고 변경된 속성만 업데이트합니다. 동선 장식은 개수를 제한하고 렌더링은 requestAnimationFrame으로 묶습니다. 히스토리는 최대 100개 작업/20MB 차분으로 제한합니다.
